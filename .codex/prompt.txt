# Codex Project Guidelines

## Mission
Build production-grade developer utilities that developers actually npm install today.

## What to Build

### Good Projects (Ship These)
- **CLI tools** — Repo scaffolders, deploy CLIs, code generators, developer tools
- **Libraries** — TypeScript utilities, API clients, validation libraries, SDKs
- **Components** — Next.js auth UI, dashboard components, form components
- **Templates** — Next.js blog starter, SaaS starter, portfolio starter
- **Plugins** — Next.js plugins, Vite plugins, ESLint plugins

### NOT This (Too Big/Bloated)
- Full-stack SaaS applications (gym management, CRM, assessment tools)
- Projects requiring >20 minutes to build
- Apps that already exist as SaaS (don't compete with established products)
- Anything without clear npm install value

## The Test
**"Would a developer npm install this TODAY?"**
- If yes → ship it
- If no → too big or too niche

## Production-Grade Checklist

Every project MUST have:

### Types & TypeScript
- [ ] Full TypeScript with strict mode
- [ ] Proper type definitions (no `any`)
- [ ] Exported types for all public APIs
- [ ] JSDoc comments on complex functions

### Testing
- [ ] Unit tests (Vitest or Jest)
- [ ] Test coverage for core logic
- [ ] Tests pass in CI

### Documentation
- [ ] README.md with: what it is, install, usage, API docs
- [ ] CHANGELOG.md (even if v0.1.0)
- [ ] LICENSE file (MIT by default)
- [ ] Code examples for every exported function

### package.json (for npm packages)
- [ ] `name` — scoped (@your-name/...)
- [ ] `version` — semver
- [ ] `description` — one sentence
- [ ] `main` / `module` / `types` — entry points
- [ ] `exports` — proper exports field for tree-shaking
- [ ] `bin` — for CLIs
- [ ] `scripts` — build, test, lint
- [ ] `devDependencies` vs `dependencies` — correctly separated
- [ ] `engines` — node version requirement
- [ ] `repository` — GitHub URL
- [ ] `keywords` — npm searchable

### For Next.js Projects
- [ ] App Router with Server Components
- [ ] Proper SSR/SSG support
- [ ] Metadata API for SEO
- [ ] Tailwind CSS or CSS Modules

### For CLI Projects
- [ ] Commander.js or Clapper for argument parsing
- [ ] `--help` output with all options
- [ ] `bin` entry in package.json
- [ ] Exit codes (0 success, 1 error)

### For Libraries
- [ ] Tree-shakeable (no side effects at import)
- [ ] JSDoc comments on all exported functions
- [ ] Zero or minimal runtime dependencies
- [ ] Works in Node.js, edge, and browser

## Tech Stack Preferences

- **TypeScript** — non-negotiable
- **Node.js 20+** — LTS
- **Next.js 14+** — App Router
- **Tailwind CSS** — for styling
- **Vitest** — for testing
- **Commander.js** — for CLIs
- **Zod** — for validation

## Project Structure

```
project-name/
├── src/
│   └── index.ts          # Main entry
├── tests/
│   └── index.test.ts     # Unit tests
├── README.md             # Docs
├── CHANGELOG.md          # Keep it updated
├── LICENSE               # MIT
├── package.json          # All fields filled
└── tsconfig.json         # strict mode
```

## Build Time Budget
- Max: 20 minutes
- If it can't be built in 20 min, it's too complex → pick a simpler idea

## Priority Order
1. Would a developer use this TODAY?
2. Is it tree-shakeable / minimal deps?
3. Is the API clean and intuitive?
4. Does it have proper tests?
